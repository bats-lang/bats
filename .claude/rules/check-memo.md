# The check memo

In check and test mode a module is not checked again when the files patsopt read for it are unchanged (bats#267, item 3; `src/cache.bats`, `tests/check-memo`). The list is the key's own, read back from it, so `patsopt --depgen` runs only when patsopt ran and passed (bats#253 measured 0.4 s a module). The graph is removed whenever the names are listed again (below), so it is never older than the files it was made from; a module that failed is never recorded and is checked again at the next run, whatever its bytes. No time is read anywhere in it. A build uses the same key and the same code (`memo_fresh`, `memo_record`, bats#323), with one more line in the list, `build/.sats_changed`, so a changed `.sats` still rebuilds every C there, since a C that is shipped is not to be trusted to a closure bats cannot prove complete. The other places a shell's status is not read are safe: the move of `<C>.key.new` to `<C>.key` (the old key was removed before patsopt ran, so a failed move leaves no key), the store of a C in the shared cache (copied beside its place and renamed, so an entry is whole or absent, and a hit is checked as patsopt's output is), and the records of `build/.bats_valid` (a record is trusted only when its key equals the one the file gives now, so a record not written, or cut short, is judged again). What comparable tools do: ccache's direct mode and depend mode hash the content of every header a compile read (the manifest of includes) and fall back to the preprocessor when one differs, sccache keys on the preprocessed output, and Bazel on declared inputs with the toolchain; none takes a time or only the translation unit's own file.

Three things are not obvious. (1) A `.sats` is digested as its interface, not its bytes: its length and sha256 are those of its text with each run of line feeds taken as one, tagged `C`, so a declaration added before a module's `#pub` ones (a static fixture's snippet) moves the `.sats` and changes no module that staloads it, as `sats_moved` has it for the `.sats_changed` stamp; a `.sats` with a line feed in a string or char literal, a `%{` or an open comment is digested as it is, tagged `R`, the same lexical scan `sats_moved` uses (`newlines_between_tokens`). The "size" of a `.sats` is the length of that text, so it is still a negative only. (2) A module's closure is what patsopt reads, so a body-only change to a staloaded dependency's `.dats` checks the modules that staload that `.dats` again (a bin that `#use`s a dependency does), which the `.sats_changed` stamp did not and which is right: patsopt reads a staloaded `.dats` (templates). (3) A file that patsopt would have read had it existed, a `.sats` of the same name earlier on `-IATS build -IATS build/src -IATS build/bats_modules`, is in no module's list, so the `names` line holds the name of every `.sats` and `.hats` of `build/`: a module added or removed (or a dependency, whose `.sats` appear in `build/bats_modules`) checks every module again. That is conservative on purpose. A project with several bins emits all the bins of a pass before it checks any (`emit_bins`, bats#353), so the first bin's key names the same `.sats` the next listing does and a cold check settles in one check (`tests/names-graph`). The digests of the files many modules share are kept for a run too: a `.sats` and every file under `build/bats_modules` (a staloaded dependency's `.dats` is several hundred kilobytes, and its sha256 in a debug bats is slow) are digested once, into one table in the memory of the process (bats#311; they were a file each in `build/.bats_dg`, about 5,000 reads and an open each in an unchanged check of quire's size), and looked up by the other modules; a module's own `.dats` is hashed where it is needed. What is proved: every read and write of the two arrays by its index, and the termination of every loop; what is not: a slot is an int read back from memory, which has no index in its type (the index is a plain int array, not array's `iarr`), so `slot_read` takes a value outside the bytes written to be an empty slot, which is a miss and digests the file again. The listing (`build/.bats_names`) is made once after anything that adds, removes or moves such a file (`names_set_fresh(false)`: a `.sats` emitted, which is `touch_sats_stamp`, `build/` swapped in by `cache_swap`, the orphans pruned) and its sha256 is read at each lookup; before this it was a `find` and a sort for each module, twice, which made a no-change check 9 to 12 s slower than main's.

What is not proved, and is checked another way: that `patsopt --depgen` lists every file a module's check reads (it is the walk `BATS_CACHE_DIR`'s key has used since bats#250; its limits are patsopt's, and a `staload` of a file by a name built from the environment is not seen); that the squeezed text means what the original does (the lexical scan is a function of the bytes and is tested, `tests/sats-moved`, not proved); that renaming into place is atomic on the file system in use (POSIX says it is on one file system; a `build/` on a file system that is not is not covered); and that `names` is read before patsopt runs and the closure after, with nothing between them that changes a `.sats` (bats holds the project's lock, so only bats itself does, and all the emissions are done by then). `--cold` on main is the detector for a closure that missed a file, as it is for `build/` in quire. `patsopt --depgen` is started by `sh` in every case and is held to `BATS_PATSOPT_TIMEOUT_S` and `BATS_PATSOPT_MEM_MB` by the same wrapper `patsopt_only` uses (time: status 124, memory: 125, the same error naming the module; a depgen that hangs once hung a `check` past the cap); `tests/patsopt-cap` plays a hanging `--depgen` and leaves depgen out of its count of who started patsopt, since sh starts it whether a cap is set or not. A key that would reach 524288 bytes (the most bats writes) is not written, and `-v` says so; the module is then checked again at each run. The root package of a library (`build/src/lib.dats`) was checked at every `bats check` whatever its inputs; it is skipped now by the same key. Hashing less would mean trusting a `.dats.src` sidecar for a file bats wrote (a kill between the two writes leaves a `.src` that is not the `.dats`'s), which is not done.

Neither an object nor a key of an object is kept here: the shared cache holds patsopt's C, which
names the project's files relative to the project, and this memo's closure lists names under
`build/`; an object's key is in build-freshness.md.
