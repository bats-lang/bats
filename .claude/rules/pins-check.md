# bats pins-check: what the review of a pure pin or relock pull request verifies, as a command (bats#427)

`bats pins-check <base> <head> [--compiler <dir>] [--repository <dir>] [--require-contains <sha>]` checks, in a git checkout of the pull request (any working tree: it reads git objects only), that the diff `base...head` (from the merge base, the pull request's own diff) is a pure move of pins. It is a subcommand written in bats (`src/pins_check.bats`, run before bats's own arguments are read, as `affected` and `merge-proof` are; quire#646). The review of such a pull request is its output: the reviewer pastes it and confirms the diff is pins only (the review stays, the gate needs a comment; only its size shrinks). `--compiler` is a checkout of bats-lang/bats (where the commit of `.github/bats-version` is looked up), `--repository` the package repository's checkout (else `BATS_REPOSITORY`: the commits of `.github/repository-version` and of the `repository-prototype` workflow pins, and the sidecars). A checkout is needed only for a pin that moved.

Exit 0 and a line `ok   <path>` for each file checked, then `OK: <base>...<head> changes only pins`. Exit 1 and a line `NOT OK: <path>: <reason>` for every finding (it goes on after the first, so one run lists them all), with `note:` lines for what is said and not refused. Exit 2 and a line on stderr for a usage error, a checkout that is needed and not named, and a git that did not answer.

## The checks

1. **No other file.** `git diff --name-only --no-renames` lists only `.github/bats-version`, `.github/repository-version`, `bats.lock`, `.github/workflows/relock.yml` and `.github/workflows/publish.yml`; any other path is a finding naming it, an empty diff is one too, and a list longer than 65536 bytes is one. A file added whole (publish.yml new) is not a pin move: step 3 finds its lines are not pins.
2. **A pin file** (`.github/bats-version`, `.github/repository-version`) ends up as exactly one line, 40 lowercase hex digits (a file deleted, with a second line, with 39 digits or capitals is a finding); that commit exists in the checkout of its repository (`git cat-file -e <sha>^{commit}`); and the new pin is ahead of the old one: the old is an ancestor of the new (`git merge-base --is-ancestor`). If the new pin is an ancestor of the old, it is **behind**, a finding. If neither is an ancestor of the other, the two have **diverged**: a `note:` line, not a finding. Why: the old pin of many of the pull requests measured below (every pin move from the bats pin of 2026-10-16) was a commit that is on no branch of bats's main (it was dropped when main was rewritten), so no pin after it can descend from it; GitHub's compare API has the same three outcomes (`ahead`, `behind`, `diverged`, with `identical`), and only `behind` is a regression.
3. **A workflow** (`relock.yml`, `publish.yml`): each changed line, added or removed, holds a pin, a word of letters and digits that is 40 lowercase hex digits (`uses: owner/repo@<sha> # version`, an input that repeats a commit); a line whose first non-space byte is `#` is a comment and is not read (the comments that explain a pin move with it). A `+` line that names `bats-lang/repository-prototype/` has its commit looked up in `--repository`, one that names `bats-lang/bats/` in `--compiler`. The pins of third-party actions are format-checked and not looked up (no checkout of theirs is named), and a workflow pin is not compared with the old one (the pair of lines is not matched).
4. **`bats.lock`**: each added line is `<package> <version> <sha256>` (64 lowercase hex digits); its version is not older than the removed line of the same package (versions are numbers separated by dots, compared number by number; a dev version such as `2026.2.21.53844dev1` is not numbers and is a finding, since `bats lock` without `--dev` never writes one); a version that stayed with another sha256 is a finding; and the sha256 equals the sidecar `<package>/<package with / as _>_<version>.bats.sha256` of the package repository **at the commit of the head's `.github/repository-version`** (read with `git show`, never from the files the clone has checked out: the same check as `bats check-push` check 1, whose `check_entry` it calls). Only the added lines are read: a removed line, an added or removed package, moves nothing the pin is about.
5. **`--require-contains <sha>`** (40 lowercase hex digits) fails a pin that lacks a given fix: for each moved pin whose checkout has that commit (the compiler's, the package repository's; also the `repository-prototype` and `bats` pins of a workflow), the pin must be it or descend from it (`git merge-base --is-ancestor <sha> <pin>`). If no moved pin is in a checkout that has the commit, the required commit could not be shown to be contained, which is a finding. Without the option nothing is asked of the fix: the relock picked a pin that was the newest when it ran, and only the fix the reviewer names is the question.

## Decisions

* The name is the issue's (`pins-check`); `check-pins` (bats#390) is the CI inputs that move, and the two verbs do not mix.
* The diff is read as `git diff -U0` of each file, in 65536 bytes of git's stdout (`tool_output_wide` in `src/helpers.bats`, the capture of `.claude/rules/capture.md` with a bigger buffer and a flag for "there was more"); a diff longer than that is a finding, never a cut one. Lines, not YAML (quire#646: no YAML parser in this compiler).
* `check_entry`, `git_status` and `locks_result` of `src/check_push.bats`, and `word` of `src/merge_proof.bats`, are public for it, so the sidecar rule is written once.
* No mtimes, no network, no clock: the answer is a function of the git objects and the files named.

## Tested and limited

Tested (`tests/pins-check/check.sh`, git repositories planted with git: a compiler checkout with three commits and a side commit, a package repository with two versions of a package and a namespaced one, an app with a pull request branch for each case): the six fixtures of the ticket (a clean pin move, a pin that does not exist, a pin behind, a lock line backwards, a sha256 that differs from the sidecar, an extra file in the diff), and beside them the lock alone, the compiler pin alone, a namespaced package, a repository pin and a workflow pin that do not exist, a diverged pin (a note, exit 0), a version that is not in the repository, a version kept with another sha256, a new file, a changed line that is no pin, a comment line, a pin that is not hex, has 39 digits, capitals, two lines, or is deleted, no change, `--require-contains` (a pin that lacks it, has it, is it, no moved pin in a checkout that has it, a workflow pin that has it), and the arguments (no checkout named, one revision, a required commit that is not 40 hex digits, a flag twice, an unknown flag, a revision starting with `-`, an unknown revision, the repository from `BATS_REPOSITORY`).

Measured (bats#427, the pull request): the command was run on every merged pull request of the local checkouts of the repositories of the organisation since 2026-10-10 whose diff touches only the five files (123 pull requests: relock and pin pull requests of bats, bridge, pwa, quire, dom, widget, builder, gestures, html, css, json, toml, xml-tree, str, array, file, process and repository-prototype) with the compiler and the package repository at their newest main: 122 are OK and the one finding is a pull request that adds an input (`npm-ignore`) to a relock workflow, which is not a pin move. On bridge#195, whose pin of bats main lacked the fix of bats#465, the same run is OK without the option and NOT OK with `--require-contains` the commit of that fix.

Limits, said exactly: the pins of workflow lines are looked up, not compared with the old ones; a third-party action's pin is not looked up; a lock line is read with its first space and the next as separators; a diff of one file over 65536 bytes is refused; the command line is read into 4096 bytes (status 2 at 4095 or more); `base...head` needs a merge base, so two unrelated histories are an error of git (status 2); and the review of a pull request also checks that its title and body describe a pin move (the command reads the diff, not the words).
