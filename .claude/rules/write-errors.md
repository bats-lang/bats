# Write errors

A write that fails is an error, never a file taken for whole (bats#359, #360, #361, #314; the shared host's disk filled in the middle of a run and bats built from a C cut short at the byte where the write failed). Every writer of bats's own files returns a `write_result` (`src/helpers.bats`, a `datavtype`: `Wrote`, `NotWritten(io_error)` with the first error, `WriteTooLarge`), so a caller must match it or hand it to `write_settle`, which says `error: cannot write '<path>': <the system's reason> (os error <n>)` (and, for `StorageFull`, the free space of build/ as a fact: `; N MB free in build`) and fails the build, 0 or ~1; none is dropped (`write_file_from_builder`, `write_file_from_builder_m`, `write_file_from_rope`, `wbw_loop`, `writer_finish`). The first failed byte stops the write (the file package's `buf_write_byte` empties its buffer on an error, so going on would write the bytes after a gap), and `writer_finish` asks for the flush itself because the file package's `buf_writer_close` drops its own flush's error (to be reported upstream; the richer FullWrite/PartialWrite/EmptyWrite/FailedWrite of file#60 will refine `NotWritten`, nothing here waits for it: `_file_write` is `write_all`, so a write that returns wrote every byte). `relative_c` (`c_placed`: `CPlaced`, `CNotPlaced`, `CNotWritten`) no longer falls back to patsopt's C as it is when the rewritten one cannot be written (that put a C with the checkout's path in it in place, and said nothing): it removes what it wrote and the old C, and the key, dropped before patsopt ran, is not written. A module is emitted with its `<dats>.src` emptied first (`preprocess_changed`), and its .dats is not written after its .sats failed, so no hash beside a .dats or .sats cut short makes them fresh (a changed target had left the old hash and the marker already moved). The records of `build/.bats_valid/` are the one write that may find its directory missing, by design (`NotFound`: no record). The shared cache's copy (`BATS_CACHE_DIR`) is a `cp` and `mv` of the shell: its status is said as a warning, and the build goes on (the cache is not what is built, and the copy is moved whole or not at all). `tests/full-disk/check.sh` plays it: `ulimit -f` with SIGXFSZ ignored (a write past it fails with EFBIG as a write on a full file system fails with ENOSPC; patsopt, a wrapper that lifts the limit, writes what bats then rewrites), over a project whose .sats, .dats and C are of three sizes, so each limit stops the writers of the files over it: a C alone, the .dats and C, the .sats and everything bigger, and 0 (every small writer; the tools bats starts fail too); each must fail with status 1, the first error the `cannot write` line, no other write tried after it (but at 0), and the next check with no limit makes the `build/` a clean check makes, but for the records, the .sats stamp and the stash, which hold the history of the runs. Where a tmpfs can be mounted (root, or sudo with no password) a real full file system (3 MB) is played too: ENOSPC, the free space said, the check after `mount -o remount,size=64m` the clean build's. It fails on main's compiler: a C cut at the limit is accepted and `check passed` is said (the cases of the .dats, the .sats and 0 failed silently, with no error line, or with the stamp's message, not the write's).
