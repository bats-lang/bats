# Validated records and the #use memo

An unchanged `bats check` on a project of quire's size (18 dependencies, 158 `.bats` files, 4.7 MB) took 26.5 s of CPU and no longer does (bats#296; callgrind of the 189 G instructions, and gdb samples of the process for time). Where it went: opening a file or a directory with the file package copied the whole 524288 bytes of the path's array into a fresh C string (20,000 opens, 37% of the instructions in `write_borrow` and 19% more zeroing the copies), so every path is opened at its own length now (`file_open_m`, `file_exists_m`, `dir_open_m` and `file_open_n` in `src/helpers.bats`, which copy the bytes up to the first NUL into an array of that size (bats#368 removed the fixed-size wrappers that passed the builder's 524288 bytes to them); the digests of the shared `.sats` and dependency files, which were a file each at the time, are one table in the memory of the process since bats#311, described in check-memo.md); and `validate_project` lexed every source of the project and its dependencies twice, once for the safety rules and once for the call cycles (23%). What it judged is kept in `build/.bats_valid/` (`src/validated.bats`): a record named after a file's path (/ as %) holds the key of a file that passed, the sha256 of a text of the context (bats's own inputs, which are the stamp's `bats` line, and the listing of the `.bats` files of `./bats_modules`, which says which packages are installed), the package's unsafe flag (`read_unsafe_flag`, which emission reads too), the path and the sha256 of the file; a package's call-cycle check is recorded as `cycles <package>` with the path and sha256 of each of its files. A file or package is judged again when its key differs from its record, or when there is none; only one that passed is recorded, and after being hashed again and found the same as when it was keyed. No time is read. `--cold` and `BATS_COLD` judge everything and write the records again. `.bats_valid` belongs to no mark: `cache_swap` and the stamp's drop leave it alone, as its keys name bats and everything else they depend on. `-v` says each file judged (`  ~ lexed <path>`) and each package whose cycles are looked at (`  ~ call cycles of the package of <file>`), which `tests/check-validated` counts, with a case for each part of a key (the file's bytes, the unsafe flag, the listing of `./bats_modules`, the package's files) and for a record that is missing, empty, cut short, garbled or another file's. Left, by the same profile: hashing the C of each module for its object's key (a third of the time left; the sha256 package does about 80 instructions a byte), `resolve_deps` lexing every source for its `#use`s, and the builder's 512 KiB zeroed array per path and per line (bats#368: a path, line or argument is now an array of its own size).

The `#use` packages are kept by content the same way (bats#310, `src/validated.bats`'s "uses" records, read by `add_file_uses` in `src/lock.bats`): every check used to lex each `.bats` file of the project, its path dependencies and its locked packages for `#use` lines (`resolve_deps`, `collect_uses`), 8% of a check in which nothing had changed. A file that was lexed leaves `build/.bats_valid/uses <path>`, keyed by the sha256 of bats's inputs, the path and the file's bytes, holding the names its `#use` lines give (NUL-ended, a package name holds no NUL) and the sha256 of that body, so a torn or garbled record is lexed again. A record is written only into a `build/.bats_valid/` that is already there (a record never makes `build/`: a validation that fails leaves none, so the first check of a project writes none and the next writes them), only for a body that fits its builder, and only when the file still has the key it was lexed under. `-v` says each file lexed (`  ~ uses lexed <path>`), and `tests/uses-memo` checks that a `#use` added, removed or changed in place is noticed, that an unchanged file is not lexed again, and that `--cold` lexes every file.

`check_wasm_binary` (`src/build.bats`) reads a binary's `#target` line by lexing its whole source, and each pass of a build asked for every binary twice (to emit it and to check it), so quire's two binaries were lexed eight times by an unchanged check (11.7 G instructions of 46.9 G, bats#368). The target of each source is kept in memory for the run, by the sha256 of its bytes and not by its path (`bats test` rewrites the same path with other contents; a build does not change a source); a source that cannot be read is not kept.
