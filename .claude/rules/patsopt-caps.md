# patsopt caps

With `BATS_PATSOPT_TIMEOUT_S` (wall clock seconds) and/or `BATS_PATSOPT_MEM_MB` (address space, megabytes) set, every patsopt run (`patsopt_only` in `src/helpers.bats`, the one place patsopt is started) is held to them, because the GMP build of ATS2's solver can run away in time and memory on a proof the machine-integer solver answers at once (one function of quire's `library.bats` passed 6.4 GB in 14 minutes, and an earlier run was killed by the system at 9.9 GB with no module named: bats-lang/quire#594). This is a resource cap on an external process, not a runtime check of the program: the types say nothing of how long or large the solver gets. It is portable sh and kill, which POSIX has, because there is no `timeout(1)` on macOS and the process package has no setrlimit or kill. How the two are told apart (bats-lang/bats#524): a signal (a status under 0, or over 128 through sh) or the allocator's words in stderr make a run the memory cap's, and nothing else does, so the length of stderr never does. bats keeps the first 500000 bytes of stderr for its report and then reads the rest to the end and drops it (`discard_fd`), because the first version stopped reading and closed the pipe, patsopt then died of SIGPIPE writing to it (status 141 through sh) on any stderr over about 500 KB (quire's mutation check printed 641 KB of unsolved constraints), and that signal was read as the cap. A patsopt that fails with exit status 1 and a long stderr without the allocator's words is patsopt's own error with its first lines, and a patsopt that exceeds `BATS_PATSOPT_MEM_MB` (it allocates until malloc fails, then says so or aborts) is the cap; `tests/patsopt-cap/check.sh` runs both (`FAKE=noisy`, `FAKE=hog` and `FAKE=abort`). What is not portable: a system whose sh cannot lower the limit (`ulimit -v` refused, probed once) is told once and patsopt runs without the memory cap, and macOS, whose `ulimit -v` does not enforce RLIMIT_AS, is untested here; the time cap is whole seconds and needs `kill -s ALRM` and `wait` giving 128 + the signal, which POSIX's `kill -14` and every sh tried (dash) do (`tests/patsopt-cap`). Other tools' caps on a prover, for the record: Why3's manual page gives `--timelimit` in seconds (0 off, default 10) and `--memlimit` in megabytes (default none) for each prover call, which is the same pair of wall clock and memory caps; Dafny offers, besides a time limit, a Z3 resource count (`--resource-limit`, a deterministic counter that stops the solver like a time or memory limit, reproducible under load but not uniform in work), which needs a counter inside the solver, and patsopt's has none, so bats caps the process, per module.
