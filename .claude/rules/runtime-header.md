# The C runtime header and bootstrap/c

The C of `bootstrap/c` builds with no ATS2 installed (bats#283): `--to-c` writes `_bats_native_runtime.h`, a header for the ATS2 C runtime macros and prelude functions the generated C uses (the same text as the wasm build's, `put_runtime_macros` in `src/build.bats`, over libc, plus the print and exit functions), and empty stubs for the three `libats/libc/CATS` files the C names (`_bats_native_stubs`), and the Makefile compiles with `-D_ATS_CCOMP_HEADER_NONE_ -D_ATS_CCOMP_EXCEPTION_NONE_ -D_ATS_CCOMP_PRELUDE_NONE_ -D_ATS_CCOMP_RUNTIME_NONE_ -include _bats_native_runtime.h -I_bats_native_stubs`, as the wasm build does, with no warning flags turned off. PATSHOME is for running patsopt only; the compiler a normal `bats build` makes still compiles with ATS2's headers.

**The runtime header (its method).** ATS2's own headers (`ccomp/runtime/*.h`, `prelude/CATS/*.cats`) are GPL-3.0-or-later and are not copied into the tree: the repository declares no licence, and copying would carry GPL-3 into it. The header is written here, from the use sites in the C that patsopt emits (the names and shapes in `bootstrap/c`, and in the wasm fixtures' C) and from the semantics ATS2 documents for each name, with its own parameter names, its own bodies and its own structure. The names are ATS2's, since they are the interface the emitted C is written against. Where ATS2 has a macro, this has a macro with another body where the interface leaves one to choose; the arithmetic, comparison and conversion functions of the prelude are typed `static inline` functions made by two helper macros (`BATS_FN1`, `BATS_FN2`), not a copy of ATS2's macros. What each must do: a name that ends a type says which C type it is; `ATSCKpat_con0` is true for the small integer that stands for a constructor without fields, `ATSCKpat_con1` for a pointer (1024 or above, below which are the small integers) whose first word is the tag; `ATSINSmove_con1_new` and `ATSINSfreecon` allocate and free a constructor block with the C library's malloc and free; `ATSfunclo_clo` calls the code address a closure begins with (`cfun`); `ATSINStmp*`, `ATSINSmove_*` and `ATSINSstore_*` are assignments of the shapes their names give; `ATStailcal_beg/end` and `ATScaseof_beg/end` open and close a `do { } while (0)` that `break` leaves (a branch ends in `break`); the `ATSdynload*` macros declare, set and call a module's load flag. How it is tested: the fixpoint (a compiler built from `bootstrap/c` with this header regenerates `bootstrap/c` byte for byte), the whole fixture suite run by that compiler, the wasm fixtures (`tests/build-wasm`, `tests/test-wasm`, which compile with the same text), and gcc compiling every module with no warning flags turned off. `ATS_MALLOC` in the native header (`bats_alloc`) prints `bats: out of memory` to stderr and exits with status 1 when malloc answers NULL (keyword: native-malloc, bats#510): `tests/native-malloc/check.sh` builds a tiny project with `--to-c`, compiles a C program against the header it wrote that asks for `SIZE_MAX` bytes (a request no heap holds, so malloc answers NULL by the C library's own rule on Linux, macOS and the BSDs; `ulimit -v` is not enforced on macOS, and an interposed malloc is linked differently on each system, and `bats_alloc` is a static inline over malloc) through `ATS_MALLOC`, `atspre_ptr_alloc_tsz` and `ATSINScloptr_make`, requires status 1 and the message, requires a 16-byte allocation to succeed silently, and shows five mutants of the header (the NULL returned with or without the message, exit status 0, exit status 2, the exit with no message) each failing it; the wasm runtime's own malloc is used as it is. The macros of ATS2 that no emitted C names are not defined; the wasm build has always carried the macros wasm consumers (quire's C is not in this repository) might use, so that set is kept, every one written afresh, and a macro found unused by all consumers is a candidate to remove. Copying check (the `#define`s of the generated `_bats_native_runtime.h`, compared with those of ATS2's `ccomp/runtime/*.h`, `prelude/CATS/*.cats` and `libats/libc/CATS`, by a one-off script that reads both, not committed (bats#512, #513; ATS2 is the pinned GMP build)): 133 defines here, 124 with an ATS2 name, with two metrics side by side. Whitespace only: **23 have the same parameters and body**, 40 more agree only up to the names of the parameters, and 61 differ. Modulo parentheses and parameter names: **76 of 124 are identical** (the 23 and the 40, and 13 more: `ATSfuncall`, `ATSextfcall`, `ATSextmcall`, `ATSINSmove`, `ATSINSload`, `ATSINSstore`, `ATSINSxstore`, `ATSINSargmove_tlcal`, `ATSINSmove_tlcal`, `ATSINSstore_fltrec_ofs`, `ATSPMVcfunlab`, `ATSdynloadset`, `ATSdynloadfcall`), 48 differ. The normalisation: comments and whitespace are dropped (a body is its C tokens), each parameter is renamed by its position, and a redundant pair of parentheses is dropped, a pair being redundant when it holds the whole body, or one token that is not the argument list of a call, or another pair and nothing else. The third review of #287 measured 79 with its own reading of "redundant"; the recomputation with the rule above gives 76 (said on bats#510), so the 61 of the first metric overstates the difference by the 13 that are one expansion spelt with other parentheses, and 48 are different expansions (an operand order, a different but equal cast, a macro that ATS2 defines as another name). The residue is the one-line macros whose expansion the interface forces. The 23 are empty or a constant or a keyword or a name: `atsbool_true` and `atsbool_false`, `ATSextern`, `ATSstatic`, `ATSstruct`, `ATSelse`, `ATSbranch_end` (`break;`), `atspre_strlen`, `ATSPMVbool_true/false`, `ATStyclo` (`struct { void *cfun; }`, the field name is the emitted C's), and the empty markers (`ATSdynload`, `ATSbranch_beg`, `ATSextcode_beg/end`, `ATSfunbody_beg/end`, `ATSthen`, `ATSPMVempty`, `ATSINSmove_con1_beg/end`, `ATSINSmove_fltrec_beg/end`). The 40 are one token, a one-token wrapper or a declaration or statement form that has one spelling: the type wrappers (`atstkind_type(kind)` is `kind`), `ATSINSgoto(t)` is `goto t`, `ATSif(t)` is `if (t)`, `ATSreturn(r)` is `return (r)`, `ATStmpdec(n, t)` is `t n`, `ATSstatmpdec(n, t)` is `static t n`, `ATSPMVptrof(p)` is `(&(p))`, `ATSSELfltrec(r, t, f)` is `((r).f)`, `ATSmainats_0_void(e)` is `mainats_0_void()`, the literal wrappers (`(literal)`), `ATSINSmove_void(d, c)` and `ATSINSpmove_void` (`c`, which may be empty), and the empty ones with a parameter. Where another correct formulation exists the macro uses it (a cast spelt once in `BATS_CAST`, `for (;;) { ... break; }` for `do { } while (0)`, a subscript for a dereference, `->` as `.` of a dereference, a tentative definition for an initialised flag, the prelude as typed functions), and the typedefs are alphabetical, the prelude is grouped by type, and the macros are ordered by this header's own scheme (see "Order and shape", next). Whether this residue is acceptable is the owner's decision.

The generated Makefile (`bootstrap/c`, `--to-c`) has `make install`, which puts the compiler at `$(PREFIX)/bin/bats` (`PREFIX` defaults to `~/.bats`).

## Order and shape of the macros (bats#513, keyword: header-order)

The review of #287 measured a Kendall tau of 0.65 between the order of this header's macro groups and ATS2's, and noted that `atstype_var` (`char opaque[1 << 16]` in a struct) mirrored ATS2's shape. Decision: the macros are grouped by the use they have in the C a module is emitted as, in the order a module meets them, and the group's members in the order a function's text meets them (`ATScaseof_beg` before the `ATSCKpat_*` tests, `ATSINSmove_con1_beg` before `ATSINSmove_con1_new` and `ATSINSmove_con1_end` last), not alphabetical; the groups are: function bracket and linkage, temporaries, return, values, calls, moves, conditions, patterns, tail calls and labels, constructor blocks, flat records, closures, imported constants, module load, main, kinds, constants. `atstype_var` is `typedef char atstype_var[0]`: a zero-length array is all the emitted C needs of a type variable (it is only pointed to, `sizeof` 0 and alignment 1 as before), so the 64 KiB opaque struct, which was never an object, is gone.

Research (what is documented, said as far as it was found): the interface is what the emitted C is written against, so the names stay ATS2's; the macro bodies and their arrangement are the implementer's own. Google LLC v. Oracle America (US Supreme Court, 2021) held copying the Java API's declaring code to be fair use, and the case turned on the declarations' being the interface programmers know, not on the order of the files; clean-room practice (the BIOS reimplementations, the Wine and ReactOS policies of writing from documentation and behaviour, not from the other source) is about where the text came from, which this header's method section states. Not verified in this session: how musl and the BSD libcs describe their copies of an interface (the web search returned only the Google v. Oracle coverage and nothing on them). So the decision rests on the method (written from use sites and documented semantics), and the reorder removes the one residual sign of derivation that was measurable, the shared order, as the review asked; it does not claim the order is a legal requirement.

Measured with the one-off script of the copying check (the macros both headers define, 124; ATS2's order is the order patsopt emits the includes of a C file, `pats_ccomp_config.h`, `basics`, `typedefs`, `instrset`, `memalloc`, `memalloca`, `exception`, then `prelude/CATS/*.cats`, each file's first definition of a name): Kendall tau 0.6244 before (the review's 0.65 was measured with a different reading of ATS2's order), 0.0149 after. The 76 of 124 identical modulo parentheses and parameter names, and the 23 whitespace-only identical, are the same after the reorder (the order does not change a body).

## Getting the regenerated tree from CI (#532)

When the step "Verify bootstrap/c matches sources" of `check.yml` fails, the next step ("Upload the regenerated bootstrap/c") uploads `/tmp/regen`, the directory `scripts/bootstrap-c.sh` just wrote, as the artifact `bootstrap-c-regenerated-<sha>`, where `<sha>` is the pull request's head commit (the pushed commit for a push). The artifact is kept for a limited time: the tree is needed until a worker commits it, and a stale tree is useless after the next push. The tree is the compiler's own output for the checked-out merge of the head, so it is what a local `scripts/bootstrap-c.sh` writes. A worker does not regenerate locally (a long run, which is a CI job): push the `src/` or `bats.lock` change, take the run of the pushed head, `gh run download <run id> --name bootstrap-c-regenerated-<sha> --dir <dir>`, replace `bootstrap/c` with the contents of `<dir>` (`rm -rf bootstrap/c && cp -R <dir> bootstrap/c`), commit and push; the next run verifies the tree. Commit-back by a bot (git-auto-commit-action, create-pull-request) was not chosen: a push by `GITHUB_TOKEN` does not start the checks of the new head, and the artifact leaves the commit to the worker, with the tree reviewed in the diff. Only the verify step uploads; a fixpoint failure (the second regeneration) is a different defect and has no artifact.
