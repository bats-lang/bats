# The C runtime header and bootstrap/c

The C of `bootstrap/c` builds with no ATS2 installed (bats#283).

**The runtime header (its method).** ATS2's own headers (`ccomp/runtime/*.h`, `prelude/CATS/*.cats`) are GPL-3.0-or-later and are not copied into the tree: the repository declares no licence, and copying would carry GPL-3 into it. The header is written here, from the use sites in the C that patsopt emits (the names and shapes in `bootstrap/c`, and in the wasm fixtures' C) and from the semantics ATS2 documents for each name, with its own parameter names, its own bodies and its own structure. The names are ATS2's, since they are the interface the emitted C is written against. Where ATS2 has a macro, this has a macro with another body where the interface leaves one to choose; the arithmetic, comparison and conversion functions of the prelude are typed `static inline` functions made by two helper macros (`BATS_FN1`, `BATS_FN2`), not a copy of ATS2's macros. `ATS_MALLOC` in the native header (`bats_alloc`) prints `bats: out of memory` to stderr and exits with status 1 when malloc answers NULL (keyword: native-malloc, bats#510): the wasm runtime's own malloc is used as it is. The macros of ATS2 that no emitted C names are not defined; the wasm build has always carried the macros wasm consumers (quire's C is not in this repository) might use, so that set is kept, every one written afresh, and a macro found unused by all consumers is a candidate to remove. Whether this residue is acceptable is the owner's decision.

## Order and shape of the macros (bats#513, keyword: header-order)

The review of #287 measured a Kendall tau of 0.65 between the order of this header's macro groups and ATS2's, and noted that `atstype_var` (`char opaque[1 << 16]` in a struct) mirrored ATS2's shape. Decision: the macros are grouped by the use they have in the C a module is emitted as, in the order a module meets them, and the group's members in the order a function's text meets them (`ATScaseof_beg` before the `ATSCKpat_*` tests, `ATSINSmove_con1_beg` before `ATSINSmove_con1_new` and `ATSINSmove_con1_end` last), not alphabetical; the groups are: function bracket and linkage, temporaries, return, values, calls, moves, conditions, patterns, tail calls and labels, constructor blocks, flat records, closures, imported constants, module load, main, kinds, constants. `atstype_var` is `typedef char atstype_var[0]`: a zero-length array is all the emitted C needs of a type variable (it is only pointed to, `sizeof` 0 and alignment 1 as before), so the 64 KiB opaque struct, which was never an object, is gone.

Research (done for bats#513; the sources were read, not recalled). (1) What an interface is, in law: Google LLC v. Oracle America (US Supreme Court, 2021, https://www.supremecourt.gov/opinions/20pdf/18-956_d18f.pdf) held that copying the declaring code and the structure, sequence and organization of the Java API, taking "only what was needed to allow users to put their accrued talents to work in a new and transformative program", was fair use: the names and their grouping are the interface; the decision does not require an implementer to keep another order. (2) Wine rewrites the Windows headers itself (wine-devel, Header file legal issues, https://www.winehq.org/pipermail/wine-devel/2001-February/000181.html): "rewrite the header files ourselves" is the way to be sure of the licence, while a participant argues the layout may be unprotected because Wine "absolutely requires the specific header file layout" (Sega v. Accolade). Its clean-room guidelines (https://forge.fsky.io/brunodev85/wine/wiki/Clean-Room-Guidelines) concern where the text came from: "if a test program will do, don't look at any Microsoft doc or headers", and ReactOS code is off limits "not even header files"; they say nothing of the order or shape of a header. (3) musl, whose COPYRIGHT file (https://git.musl-libc.org/cgit/musl/plain/COPYRIGHT?h=v0.8.1) treats its public headers as public domain because they "intentionally contain no content which can be covered by copyright" (names and declarations), and whose maintainer, on a BSD header that is "100% code" (https://www.openwall.com/lists/musl/2013/06/28/9), separates headers that are only an interface from one that is code and notes that a rewrite is the answer to its licence: the code is where authorship is, the interface is not. (4) FreeBSD's discussion of a BSD copy of the Linux V4L2 header (https://socsvn.freebsd.org/socsvn/mirror/FreeBSD/vendor/v4l/README): "you cannot copyright an interface - its a fact rather than creative expression normally" (Alan Cox), and "typing it all in in a different order" is the way a reimplementer who does not want the original text does it, at the price of tracking fixes. What the sources do not give: no BSD libc document found describing its own copies of a GPL header (the search returned the V4L2 thread and nothing on libc), and none of these is a ruling on a macro header's order. Decision, from these: keep the names (the interface; every source treats them as free), write the bodies from the use sites (the method above), and break the order and the shape that were measurable, which costs nothing and removes the one sign of derivation a reader could point at (the "different order" practice). So the groups are reordered by this header's own scheme and `atstype_var` has another form, as the section's first paragraph says; this was already done in the source (`put_runtime_macros`) and `bootstrap/c`, and the recomputation after the research confirms it: the header written is the one measured below. The order is not claimed to be a legal requirement.
## Getting the regenerated tree from CI (#532)

Commit-back by a bot (git-auto-commit-action, create-pull-request) was not chosen: a push by `GITHUB_TOKEN` does not start the checks of the new head, and the artifact leaves the commit to the worker, with the tree reviewed in the diff. Only the verify step uploads; a fixpoint failure (the second regeneration) is a different defect and has no artifact.
