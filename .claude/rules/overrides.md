# Implement of another package's template (overrides, bats#421, bats#565)

An `implement` that replaces what another package implements is rejected before patsopt runs, with a message that names the function and the declaring package. A `#pub` template is for a dependent to instantiate, not to replace.

**What the build does.** A file's dats loads a dependency's lib.dats without an alias, and that opens none of its names. A bare `implement{} name` therefore binds only to a declaration of the file's own package, so a package may declare and implement a name its dependency declares too (toml's and array's `get`). An unqualified implement of a name only the dependency declares fails in patsopt, and is left to it. What reaches a dependency's name is the qualified `implement{} $A.name`, with `A` bound in the same file by `#use P as A` (the lib file of P), by `staload A = "<root>/src/m.sats"` (that file), or by an unaliased staload of a file of another package (its names open unqualified). Only the bound file's own `#pub` names are reached, never a module its lib file staloads, so nothing is walked. The experiment that shows this is in the pull request of #421.

**A hit.** The reached file declares the name with `#pub`, and the package that declares it also implements that name: generically, or for the same instance (the text of the `<...>` after the name, blanks removed). A name a package leaves for its dependents to implement is an extension point and is not rejected: promise's `dispose`, which bridge implements for each payload type, is implemented by promise only for a few concrete types.

**Builds.** The implement, the binding, the declaration and the declarer's implement must be live in one build (native or wasm, test or not). A `#target` or `$UNITTEST` block that the emitter blanks (`next_state`) holds no live fact, so a use the build loads nothing for creates no rejection. Every fact is read once with the builds it is live in, so the record of a file does not depend on the build.

**Limits of the replace check.** A type spelled another way than the declarer's instance is not matched. A staload whose path leaves the package is followed only for the unqualified case above and for `staload A = "<root>/src/m.sats"`. Every package of `./bats_modules` is checked, so a dependency replacing its own dependency's implement is found as a direct one is. A package is named by its root under `./bats_modules`, the text of its `#use`; the package itself is package 0.

**Names and bounds.** Names are compared in full. The length of a name is bounded by the array allocation, in the type of `name_of_range`; a name longer than that is a fact of its own (`OversizedName`) and the check reports the file, since it cannot compare it. Offsets and package numbers carry their bounds in their types.

**Records.** The facts of a file are kept in `build/.bats_valid/facts <path>` as the `uses` records are (`validated.md`): the key holds the sha256 of bats's inputs, the path and the bytes of the file, so a record written by another compiler is not trusted, and `-v` says each file lexed (`  ~ facts lexed <path>`). `tests/foreign-implement` plays the rejected cases, the accepted ones and the record.

## The orphan rule (bats#565)

**The rule.** An `implement` of a template that another package declares (`#pub fun{...} name`, with the braces before the name) is for a type of the implementing package: the instance (the text of the `<...>` after the name) must name a type that a file of the implementing package declares, and the same instance is implemented once by the package. It does not depend on what the declaring package implements, now or later (quire#890: `dispose<Int>` was refused only because promise implemented it, while `dispose<jchunk>` beside it was accepted). The template of the package itself, and an ordinary function (not a template), are not under it; an ordinary function keeps the check above.

**Which types count.** `datatype`, `datavtype`, `dataviewtype`, `abstype`, `absvtype`, `absviewtype`, `abst@ype`, `absvt@ype` and `absviewt@ype`, public or not, and the names after an `and` of their group, in any file of the implementing package (`DeclaresType`). A `typedef` is an alias, not a type (`typedef x = int` makes `dispose<x>` the instance `dispose<int>`), so it does not count. With several arguments (`a, b`, split at the commas outside brackets) one owned argument is enough, as in Rust's rule that one of the types is local. The head of an argument is its type: `list_vt(mine)` has the head `list_vt`, which is a prelude type, as Rust's `Vec<Local>` is not local. A head written `$A.t` is owned when the alias `A` of the same file binds a file of the implementing package that declares `t` (`staload A = "<root>/src/m.sats"`); one bound by `#use P as A` is the package P's, and the finding names P.

**What is reported.** Each finding names the instance, the template and its package, the type, and who owns it ("a type of the package 'bridge'", or "a base or prelude type, or one that this package does not declare"), and says what to do: a type of the implementing package, a wrapper type of its own, or ask the package that owns the type to implement it. The kinds are in `refusal` (`overrides.bats`): `GivesNoInstance` (`implement{} $P.hook`: every type), `NamesNoType`, `NotOwnType` and `ImplementedTwice` (the second implement of one instance by one package, live in one build; a package that spells the same name for a type of its own in another package is not a duplicate, since the owner is part of the key).

**Warning first.** The rule refuses code that compiled, so in the first compiler version that has it the findings are warnings (`warning:`, printed before the errors, the status unchanged), and `BATS_ORPHAN_ERROR=1` (anything but 0) makes them errors, as Swift's SE-0364 warns first and GHC's `-Worphans` is a warning only. The second step (error by default, the variable gone) is the p2 ticket filed with the change. What bats#421 refuses stays an error in this version: when the declaring package implements the instance the dependent replaces, the check prints the orphan finding as a warning and the replace error as before; with `BATS_ORPHAN_ERROR=1` the orphan error stands alone, so the error for an instance is the same whether the declaring package implements it or leaves it out (`orphan_dep_without` and `orphan_dep_with` in `tests/foreign-implement` have the same expected text).

**Limits.** Types are matched by name within the implementing package, so two modules of a package that each declare a type of one name are one type to the check. The instance is compared as text with blanks removed. The type groups joined with `and` are read in code and in a `#pub` declaration; a type declared inside a `#target` or `$UNITTEST` block is live in the builds that keep the block.

**Research** (bats#565): Rust RFC 2451 (local type, no uncovered parameter before it, an error since 1.0), Swift SE-0364 (a warning for a retroactive conformance, `@retroactive` to say it is meant), GHC `-Worphans` (a warning only). The comment on the ticket has the sources and the choice.
