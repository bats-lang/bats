# Build freshness

A build reuses what an earlier build produced when it is still fresh; the Rust bats rewrote every `.sats` and `.dats` on every build, so its cache (input mtime equal to the recorded one) reran patsopt on everything. A `.bats` is emitted again only when its bytes are not those its `.dats` was emitted from (their sha256, kept in `<dats>.src`; an mtime cannot tell, since a relocked dependency's files keep their archive's older mtimes, `tests/source-replaced`); its `.sats` is written only when its bytes change, and then `build/.sats_changed` is written. Nothing reads a time to decide what is fresh (bats#254: a build and its inputs are made in one whole second, a stash is moved with its mtimes, a file is touched or replaced with an old time; each gave a build that did the work again, or not at all). A module's C and its object each have a key beside them, `<C>.key` and `<object>.key`, written after the tool passed and removed before it runs: for a C the check memo's key (check-memo.md: the sizes and sha256s of the files patsopt read for the module, its `.dats` and every `.sats`, `.hats` and staloaded dependency `.dats` it reaches, and the names of the project's `.sats` and `.hats`), and in a build also `build/.sats_changed` (bats#323: a template body changed in a dependency's `.dats`, its `.sats` the same, is instantiated again in the C of every module that staloads that `.dats`, which the key of the module's own `.dats` and the stamp did not see, so a dependent's C and object kept the old body), for an object the sha256 of its C, and for a native object also a line naming its profile, debug or release (bats#320: the two profiles share `build/`, a native object's cc flags are the profile's, `-g -O0` or `-O2`, and a release object was reused by a debug build and the reverse), so a build of the other profile makes the object again; the C's key and a wasm object's name no profile, since patsopt's C is the same in both and the wasm cc flags are fixed (`-O2`, no `-g`), so a wasm object is kept across debug and release builds (the other flags, the target and the mode are in `build/.bats_stamp`, which drops a `build/` that differs). An output is fresh when it is there and its key equals the one its inputs give now; the sizes are compared first, and a different size is a changed file with nothing hashed. A key that is missing, short or garbled makes its output again. `build/.sats_changed` is written whenever an emitted `.sats` changes, with new bytes each time (the sha256 of what it held), so in a build a change to a `.sats` rebuilds every module's C, as before (a check and a test do not read it: see check-memo.md), and a body-only change rebuilds its own module and the modules that staload its `.dats` (a dependent of a library), no others (`tests/sats-change`, `tests/build-content-keys`). The same keys serve the dependencies under a namespace (bridge, dom), the extra modules of a dependency, the wasm objects, the binary's own module and the entry's object (the entry's C is made again by every build, and an object is made again only when that C differs). The cost: every no-change check reads and hashes each module's `.dats` and each C once; the tests are `tests/build-content-keys`, which plays the no-change runs after a cold one with no settling, every file of `build/` given a time in the future and long ago, a changed body of the same size, a changed `.sats`, and a garbled or missing key.

## What of bats.toml reaches build/ (bats#381)

A `build/` is restored by content, so what matters of `bats.toml` is whether a field changes what bats writes into `build/` (the emitted modules, the C, the objects, the link) with the sources the same, and what judges it. Every read of the file is below (`src/lock.bats`, `src/commands.bats`, `src/docs.bats`), and all of them are `read_toml` / `read_manifest` of `src/helpers.bats`: the file is read whole (`read_whole_m`, no ceiling but an arena's, 256 MiB, above which the read is an error) and then parsed (before this, `upload`, the docs and the version writer read the first 8192 bytes, and `read_toml` the first 65536, so a longer manifest was read cut; `write_with_version` zipped the cut copy into the archive; `tests/toml-fields` has a library manifest of 8840 bytes whose `name` is past 8192). The whole document is parsed first, and a syntax error anywhere is an error of every command, since nothing of it is cached). Target and mode are not fields: they come from the command line and the `#target` lines of the sources, and are the stamp's `mark` line. `tests/toml-fields` plays each row: a `build/` made under one manifest and restored under the other is kept whole and equals the cold build's `build/` (the objects aside, whose debug info names their directory), or the change is refused or rebuilt as the row says.

| field | effect | reaches `build/` | judged by |
|---|---|---|---|
| `[package] name` | names the archive of `upload`, the docs, and the package in a constraint's error text | no | nothing needs to: read whole at each command (`read_manifest`) |
| `[package] kind` | `build` and `run` refuse `lib`; `check` says library or binary and writes docs for a library; a path dependency in a `lib` is an error; default `lib` | no: `do_build` walks `src/` and `src/bin/` whatever the kind (a flip leaves the other kind's modules in `build/`, never linked) | read whole at each command (`project_kind`, `do_upload`, `generate_lib_docs`), never from `build/` |
| `[package] version` | the version `upload` injects, and the version of an installed dependency (`toml_version_is`) | no | read whole at each command (`package_value`, `write_with_version`, which zips the manifest whole into the archive) |
| `[package] trunk` | the branch `upload` takes a version from | no | read whole at each command (`package_value`) |
| `[package] ats2` | read by nothing; only its type (a string) is checked | no | n/a |
| `[package] unsafe` | a `$UNSAFE` block is emitted in an unsafe package and an error in a safe one; the dependencies are always emitted as unsafe | yes, the emitted `.dats` of the package's own modules, and only where the source has a `$UNSAFE` block | validation: its record's key has the flag, and it runs before any emission in `check`, `build`, `test` and `run`, so the flag false over a `build/` made with it true is an error; a failed emission leaves its `<dats>.src` empty, so it is never fresh. One reader of the flag, `read_unsafe_flag`, reads the whole file (no ceiling) for emission and validation |
| `[dependencies]` keys and constraints (`>=`, `!=`) | with a `bats.lock`, a locked version a constraint rules out is an error; without one, a package already in `bats_modules` is kept and the constraint is not applied to it (as the Rust bats) | only through the sources of `bats_modules`, which are keyed by content (`<dats>.src`, the closure keys): a relock that changes a version replaces its files and the modules are made again | the lock check (`walk_locked`), then content |
| `[dependencies]` `{ path = ... }` | the directory is copied afresh into `bats_modules/<name>` before each build | only through those sources | content |
| any other key or table (`[build]`, `[test]`) | none: bats reads none | no | n/a |
