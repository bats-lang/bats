# ATS2 install and the setup commands


**bats uses only an ATS2 it made whole (ats2 made whole, bats#264).** The `-int` build of ATS2 computes its constraint solving in C `int` and accepts false statements, which the GMP build CI pins does not, so a local check on an `-int` toolchain can pass what CI refuses. The owner ruled (2026-10-25) that the way to keep it out is to use no toolchain that bats did not make, not to ask a toolchain what it is: a probe of the solver can be wrong or give no answer, and a marker bats writes cannot.

* **The install** (bats runs curl, tar, make and git through the process package; no package of the repository is an HTTP client, and TLS is not reimplemented here). So `~/.bats/ats2` is a complete toolchain with its marker or it is absent, whatever kills a run: there is no window with a toolchain and no marker. A marker that cannot be written fails the install with the write's line and leaves no `ats2`. A leftover `ats2-temp` and `ats2-download.*` of a killed run are removed at the start of the next install: they are the only things bats removes by itself (`rm -rf` runs on those and on the run's own download directory).
* **Every command that needs patsopt** (`build`, `check`, `test`, `run`, `ats2 install`) anything else (a developer's own toolchain, an `-int` build) stops, says that bats never deletes what is at `~/.bats/ats2` by itself and names `bats ats2 install --force`. Nothing is deleted or downloaded.
* **`--force`** is the one way to replace what is at `~/.bats/ats2`, and the only thing that deletes it (the owner's ruling, "allow an explicit force install ats2 command"). It builds in `ats2-temp` and checks it exactly as the plain install does, and only then removes `ats2` (whatever is there; a link is removed itself and never what it points to) and renames `ats2-temp` into place, so a build that fails leaves what was there untouched. It installs again over the pin's own toolchain. A run killed between the removal and the rename leaves no `ats2`, and the next plain install installs. `--force` is accepted once and only on `ats2 install`; elsewhere, twice, or with any other word or option it is a usage error (exit 1), checked in `force_misuse` and `count_force` of `src/bin/bats.bats` (`--force` is a flag, so `count_positionals` does not take it for `--filter`).
* **Two installs at once** take turns: the file package's `fd_lock` on `~/.bats/ats2.lock` is held while ats2 is installed, and what is there is judged again under it.
* A test that makes a toolchain of its own in a private HOME marks it with `bats ats2 marker`: the marker text comes from the compiler under test, so the pin's three constants are read by no second parser and no non-bats file of ours holds them (no shell helper file exists).
* What is not done: asking ATS2 upstream for a way to name its solver; the owner will not file it.

**Why the retry bound is 5 (bats#509).** A run goes round again only when it lost the move and then found the target absent or empty, that is, when another run's `rmdir` (or the winner's own cleanup after a failure) emptied it in the few microseconds between this run's failed `rmdir` and its look. Each other run does one `rmdir` and one `mv` per attempt of its own, so it can empty the target for this run once; with any number of contenders each one that finishes leaves a clone, which ends the loop at the next look. A normal race therefore ends after one loss and at most one retry. The bound does not count runs: it is there so that a target that keeps being made and unmade by something outside (a program that removes the directory again as fast as it appears) ends in an error that says so and leaves the directory as it is, instead of a loop that never ends. 5 is a small number with room above the 2 attempts a race needs; no measurement picks 5 over 4 or 8, and nothing depends on the exact value (a lower bound only makes that error come sooner). **The mode read can lose to a rival too (bats#580).** The target is tested as a directory and then read with `ls -ld`; a rival's `rmdir` in between makes `ls` fail, and an empty mode made `chmod u=,g=,o=` take every permission from the run's own sibling, which `rm -rf` could then not remove (a non-root runner: `Permission denied`, an unreadable `.new.` directory, and the artifact upload of `kept/` failed on it). A mode that is not nine characters is now a lost move like a failed `rmdir`: the target is judged again and the sibling's mode is untouched. `tests/clone-repository` plays it with a stand-in `ls` (as a non-root user the old code fails there with the `rm` error).
