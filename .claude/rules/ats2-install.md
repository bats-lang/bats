# ATS2 install, the solver probe and the setup commands

`bats ats2 install` installs the ATS2 bats runs (patsopt, the GMP build) into `$HOME/.bats/ats2`; `bats clone-repository <commit> --repository <dir>` clones the package repository at a full commit; `bats record-commit <commit>` checks a commit is in the repository of the working directory. They are the three steps of the setup action (`.github/actions/setup`) after bats is built from `bootstrap/c`, as subcommands and not scripts, on the owner's ruling (bats#283); the command word must match exactly, and a further argument, a word after `--` and an unknown option are usage errors (exit 1). `ats2 install` takes no options: the pin (`ATS2-Postiats-gmp-0.4.2`, its https URL, its SHA-256) is the three constants of `src/ats2.bats` and nowhere else (`bats check-pins` fails a workflow or action that names a tarball or a digest, or a pin that is not a SHA-256 and an https tarball). It downloads with `curl` (connect timeout 20 s, 900 s in all, 3 retries) into a directory of its own made by `mktemp -d` (bats runs curl, tar, make and git through the process package; no package of the repository is an HTTP client, and TLS is not reimplemented here), checks the download with bats's own SHA-256 against the pin before unpacking, unpacks with `tar --no-same-owner` and builds patsopt in `~/.bats/ats2.new`, moves it into place whole, and then bats writes `~/.bats/ats2/.bats-ats2` (the pin's name and SHA-256) through `write_settle`, last (bats#372: the shell no longer writes it). A marker that cannot be written fails the install with the write's line and removes the toolchain the run just moved, marker file included whatever it holds (MOVED_CLEAR, `write_marker`, bats#372: a failed write can leave the whole pin in the marker, when the failure comes at the flush after its bytes, so a marker file is not kept; the move put this run's own directory there). The message is the removal's own status: "was removed again" only when `rm` exited 0, else it says the toolchain is still there and must be moved away. So a failed install never leaves a toolchain that a later run would take for a complete one, or for a foreign one; a run killed between the move and the marker's write leaves one, which is the window this design accepts. Two installs at once take turns: the file package's `fd_lock` on `~/.bats/ats2.lock` is held while ats2 is installed, and what is installed is judged again under it. A marker equal to the pin's with `bin/patsopt` there is already installed and nothing is done; a marker of another pin is replaced, and so is an empty directory; anything else at `~/.bats/ats2` that bats did not make (a directory with other files, a link to one) is refused with a message, before anything is downloaded, and left as it was (`rm -rf` is only ever run on bats's own marked toolchain, on the one a run just moved in when its marker failed (MOVED_CLEAR), and on its own temporary directories); `bin/patsopt` with no marker (a developer's own toolchain, or an `-int` build) is used as it is, never replaced, and **every process that runs build, check, test, run or ats2 install checks it and says what it found, once, on stderr** (bats#264): the `-int` build of ATS2 does its constraint solving in C `int` and accepts false statements, the GMP build CI pins does not, so a local check with an `-int` build can pass what CI refuses. The check is a probe (`probe_solver`, `PROBE_SOLVE` in `src/ats2.bats`): patsopt `-tc` is run on a control (a true statement, which must be accepted, else there is no answer) and then on the statement of the issue (a false one: the byte swap of two 16-bit halves, `h` and `l` below 65536, equal to `l`, with the conclusion `1 == 2`), in a temporary directory of the run's own (`~/.bats/ats2-probe.XXXXXX`, removed on exit). The answer is patsopt's exit status, no name or path: accepted is the `-int` build (a warning, "... accepts a false statement, so it is the -int build ...", with how to get the pinned one), refused (status 1) is not it (a note), and no answer ("cannot tell which constraint solver it has") is a warning too. It is a warning, not an error, since a user who knowingly uses such a toolchain keeps what they installed, and bats replaces only what it made. The probe's waits are bounded, and no file's time is read: a patsopt not answered at 20 s is sent TERM, and KILL at 25 s (the GMP build runs past 100 s on the false statement here, which is how it is told apart from `-int` as "cannot tell"), and a patsopt killed together with its shell gives no status, which is no answer and is not kept (a status of 143 or 137 is taken for the cap). An answer of accepted, refused or past the cap is kept in `~/.bats/ats2.solver` as `<cksum of bin/patsopt> <20|21|22>` (the bytes, not the path, so a changed toolchain is probed again and a renamed one is not), written by bats through `write_settle`, as every file bats writes (#359): the shell only runs patsopt and says its status, and bats writes the probe's two sources into a directory the shell made with mktemp and removes whatever the run found. A control failure, a patsopt that dies without an answer and one that ends by a signal or with a status other than 1 are not kept. Out of scope here: asking ATS2 upstream for a way to name its solver (a `patsopt --version` that says GMP or `-int`), which would replace the probe. The tests that put a stand-in `bin/patsopt` in a private HOME without a marker write the cache for it first (`ats2.solver` with its cksum), so the probe does not run patsopt in the counts they make; `tests/ats2-solver` plays the probe itself (accepts, refuses, hangs, dies, fails the control, the cache, a changed patsopt, HOME unset, a patsopt that kills its parent). What a killed run left (`ats2.new`, `ats2-download.*`, an old `ats2.tgz.part`) is cleared at the next install. `bats build`, `check`, `test` and `run` call the same function when `bin/patsopt` is missing (the old unverified curl install is gone). libgmp and its headers are the system's. The other two print `NAME=VALUE` (`BATS_REPOSITORY=<dir>`, `BATS_COMMIT=<commit>`) on stdout and everything else on stderr, so a CI step redirects stdout to its environment file (GITHUB_ENV's format) and bats knows no CI; a directory with a control character in its name is refused, since the line could not hold it. Both want a full commit (40 lowercase hex digits, never a branch or tag). `clone-repository` deletes nothing that this run did not make: a directory that is a git repository is used only when its `origin` is the pinned repository's URL (then fetched and checked out in place; a clone already at the commit is left alone), an absent or empty path gets a clone made in a sibling directory of the run's own (`<dir>.new.XXXXXX`, holding a `.bats-clone-pending` marker with the pid of its shell while it is made; the next run removes a marked sibling only when that pid is no longer alive, so a killed run's sibling goes and a sibling whose shell lives on (bats killed alone: the shell goes on to its clone, which it moves into place) is kept, never removed under a writer) and moved into place (`rmdir` of an empty target, which keeps its mode, setgid and sticky bits included, and is made again if the move fails, so a directory with anything in it can never be replaced), removed again by a trap on any failure and on INT and TERM, together with the parent directories the run made for it (none that were there before, so a failed `a/b/c` leaves `a` as it was), a symbolic link is refused, and every other path (any other directory, a git project of the user's, a file) is refused and left exactly as it was; a failed run leaves the directory as it was. The repository's URL is a constant in `src/setup.bats` and the tests redirect it with git's `url.<base>.insteadOf` in the environment. The setup action fails when the pinned bats commit predates this change (no `_bats_native_runtime.h` in its `bootstrap/c`) and lets only a single well-formed `NAME=VALUE` line reach `$GITHUB_ENV` (an old bats prints its usage and exits 0 for a command it does not know). Tests: `tests/ats2-install`, `tests/clone-repository`, `tests/record-commit`.
