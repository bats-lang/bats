# ATS2 install and the setup commands

`bats ats2 install [--force]` installs the ATS2 bats runs (patsopt, the GMP build) into `$HOME/.bats/ats2`; `bats clone-repository <commit> --repository <dir>` clones the package repository at a full commit; `bats record-commit <commit>` checks a commit is in the repository of the working directory. They are the three steps of the setup action (`.github/actions/setup`) after bats is built from `bootstrap/c`, as subcommands and not scripts, on the owner's ruling (bats#283); the command word must match exactly, and a further argument, a word after `--` and an unknown option are usage errors (exit 1). The pin (`ATS2-Postiats-gmp-0.4.2`, its https URL, its SHA-256) is the three constants of `src/ats2.bats` and nowhere else (`bats check-pins` fails a workflow or action that names a tarball or a digest, or a pin that is not a SHA-256 and an https tarball).

**bats uses only an ATS2 it made whole (ats2 made whole, bats#264).** The `-int` build of ATS2 computes its constraint solving in C `int` and accepts false statements, which the GMP build CI pins does not, so a local check on an `-int` toolchain can pass what CI refuses. The owner ruled (2026-10-25) that the way to keep it out is to use no toolchain that bats did not make, not to ask a toolchain what it is: a probe of the solver can be wrong or give no answer, and a marker bats writes cannot.

* **The install** downloads with `curl` (connect timeout 20 s, 900 s in all, 3 retries) into a directory of its own made by `mktemp -d` (bats runs curl, tar, make and git through the process package; no package of the repository is an HTTP client, and TLS is not reimplemented here), checks the download with bats's own SHA-256 against the pin before unpacking, unpacks with `tar --no-same-owner` and builds patsopt in `~/.bats/ats2-temp`. bats then writes `.bats-ats2` (the pin's name and SHA-256) inside `ats2-temp` through `write_settle` (`write_marker`), the shell `PLACE` checks that the marker is the pin's and `bin/patsopt` is executable, and one `mv` renames `ats2-temp` to `ats2`. So `~/.bats/ats2` is a complete toolchain with its marker or it is absent, whatever kills a run: there is no window with a toolchain and no marker. A marker that cannot be written fails the install with the write's line and leaves no `ats2`. A leftover `ats2-temp` and `ats2-download.*` of a killed run are removed at the start of the next install: they are the only things bats removes by itself (`rm -rf` runs on those and on the run's own download directory).
* **Every command that needs patsopt** (`build`, `check`, `test`, `run`, `ats2 install`) looks at `~/.bats/ats2` through `STATE` in `src/ats2.bats`, whose exit status is read once into `ats2_state` (Whole, Absent, NoMarker, OtherPin, NoPatsopt, StateFailed), and `ats2_install_mode` (PlainInstall, ForcedInstall) says whether a rename replaces: absent, installs; the pin's marker with `bin/patsopt`, uses it (`ats2 install` says it is installed); anything else (no marker: a developer's own toolchain, an `-int` build, an empty directory, a directory with other files, a link; another pin's marker; the pin's marker and no `bin/patsopt`) stops with exit 1 and an error that names what it found (no marker, or the marker's pin and the pin this bats needs), says that bats never deletes what is at `~/.bats/ats2` by itself and names `bats ats2 install --force`. Nothing is deleted or downloaded. With `HOME` unset bats has no path for a toolchain and fails as before.
* **`--force`** is the one way to replace what is at `~/.bats/ats2`, and the only thing that deletes it (the owner's ruling, "allow an explicit force install ats2 command"). It builds in `ats2-temp` and checks it exactly as the plain install does, and only then removes `ats2` (whatever is there; a link is removed itself and never what it points to) and renames `ats2-temp` into place, so a build that fails leaves what was there untouched. It installs again over the pin's own toolchain. A run killed between the removal and the rename leaves no `ats2`, and the next plain install installs. `--force` is accepted once and only on `ats2 install`; elsewhere, twice, or with any other word or option it is a usage error (exit 1), checked in `force_misuse` and `count_force` of `src/bin/bats.bats` (`--force` is a flag, so `count_positionals` does not take it for `--filter`).
* **Two installs at once** take turns: the file package's `fd_lock` on `~/.bats/ats2.lock` is held while ats2 is installed, and what is there is judged again under it.
* **Tests** (`tests/ats2-install`): the pin check, a failed download or build leaves nothing, a fresh install and the second run, two at once, for each of build, check, test, run and ats2 install the cases no marker / another pin's marker / the pin's marker / absent, a stand-in `mv` that reads the marker inside the directory it renames and kills bats right before or right after the rename, a leftover `ats2-temp`, a marker that cannot be written (a directory at its place, a file-size limit), each `--force` case and its usage errors. A test that makes a toolchain of its own in a private HOME marks it with `bats ats2 marker > <home>/.bats/ats2/.bats-ats2`: the marker text comes from the compiler under test, so the pin's three constants are read by no second parser and no non-bats file of ours holds them (no shell helper file exists).
* What is not done: asking ATS2 upstream for a way to name its solver; the owner will not file it.

`bats build`, `check`, `test` and `run` call the same function (`ats2_ensure`) when `~/.bats/ats2` is absent. libgmp and its headers are the system's. The other two print `NAME=VALUE` (`BATS_REPOSITORY=<dir>`, `BATS_COMMIT=<commit>`) on stdout and everything else on stderr, so a CI step redirects stdout to its environment file (GITHUB_ENV's format) and bats knows no CI; a directory with a control character in its name is refused, since the line could not hold it. Both want a full commit (40 lowercase hex digits, never a branch or tag). `clone-repository` deletes nothing that this run did not make: a directory that is a git repository is used only when its `origin` is the pinned repository's URL (then fetched and checked out in place; a clone already at the commit is left alone), an absent or empty path gets a clone made in a sibling directory of the run's own (`<dir>.new.XXXXXX`, holding a `.bats-clone-pending` marker with the pid of its shell while it is made; the next run removes a marked sibling only when that pid is no longer alive, so a killed run's sibling goes and a sibling whose shell lives on (bats killed alone: the shell goes on to its clone, which it moves into place) is kept, never removed under a writer) and moved into place (`rmdir` of an empty target, which keeps its mode, setgid and sticky bits included, and is made again if the move fails, so a directory with anything in it can never be replaced; bats#509: runs for one target at the same moment race for that move, and `mv` onto a directory another run just made would put this run's sibling inside it, so after the move the run looks for its own sibling's name inside the target and, if it is there, takes it out again; a run that lost the move judges the target again as it does at the start (a clone of the package repository is used or is already at the commit, exit 10; anything else is refused; an empty one is tried again, five times at most: the bound guards against a stuck state, not a count of runs, see below), so the loser exits 0 like the winner and prints no `rmdir` or `mv` error), removed again by a trap on any failure and on INT and TERM, together with the parent directories the run made for it (none that were there before, so a failed `a/b/c` leaves `a` as it was), a symbolic link is refused, and every other path (any other directory, a git project of the user's, a file) is refused and left exactly as it was; a failed run leaves the directory as it was. The repository's URL is a constant in `src/setup.bats` and the tests redirect it with git's `url.<base>.insteadOf` in the environment. The setup action fails when the pinned bats commit predates this change (no `_bats_native_runtime.h` in its `bootstrap/c`) and lets only a single well-formed `NAME=VALUE` line reach `$GITHUB_ENV` (an old bats prints its usage and exits 0 for a command it does not know). **Why the retry bound is 5 (bats#509).** A run goes round again only when it lost the move and then found the target absent or empty, that is, when another run's `rmdir` (or the winner's own cleanup after a failure) emptied it in the few microseconds between this run's failed `rmdir` and its look. Each other run does one `rmdir` and one `mv` per attempt of its own, so it can empty the target for this run once; with any number of contenders each one that finishes leaves a clone, which ends the loop at the next look. A normal race therefore ends after one loss and at most one retry. The bound does not count runs: it is there so that a target that keeps being made and unmade by something outside (a program that removes the directory again as fast as it appears) ends in an error that says so and leaves the directory as it is, instead of a loop that never ends. 5 is a small number with room above the 2 attempts a race needs; no measurement picks 5 over 4 or 8, and nothing depends on the exact value (a lower bound only makes that error come sooner). **The mode read can lose to a rival too (bats#580).** The target is tested as a directory and then read with `ls -ld`; a rival's `rmdir` in between makes `ls` fail, and an empty mode made `chmod u=,g=,o=` take every permission from the run's own sibling, which `rm -rf` could then not remove (a non-root runner: `Permission denied`, an unreadable `.new.` directory, and the artifact upload of `kept/` failed on it). A mode that is not nine characters is now a lost move like a failed `rmdir`: the target is judged again and the sibling's mode is untouched. `tests/clone-repository` plays it with a stand-in `ls` (as a non-root user the old code fails there with the `rm` error). Tests: `tests/ats2-install`, `tests/clone-repository`, `tests/record-commit`.
