# Machine slots

With `BATS_SLOTS` set (1 to 64; a larger number is 64, anything else is said and ignored), `check`, `build`, `test` and `run`'s build also hold one of that many machine slots, after the project's lock: `flock(2)` on `<BATS_LOCK_DIR>/slot-<i>.lock` (`BATS_LOCK_DIR` defaults to `~/.cache/bats`, made when missing), the files and convention of gen-pwa test's `PWA_TEST_SLOTS` and `PWA_TEST_LOCK_DIR` (bats-lang/pwa#82), so one directory given to both is one pool. Each free slot is tried in turn; when none is, bats says `waiting for another bats on this machine (N at once, BATS_SLOTS; <dir>/slot-0.lock was last taken by bats build in <directory>)` (the holder writes that note as the slot's file's first line and clears it as it releases the slot) and waits for slot 0. The kernel releases a slot however bats ends; what bats starts inherits it, as it inherits the project's lock. While it holds a slot, what bats starts gets `BATS_SLOT_HELD`, the slot's file, and a bats that finds that file locked by another open runs in its parent's slot instead of waiting for one (a command make starts runs in its implicit job slot); a `BATS_SLOT_HELD` whose slot no one holds is ignored. Unset or empty, nothing is read, made or said. The Rust bats had no machine-wide limit (`tests/machine-slots`).

**Refused (bats-lang/bats#464).** With `BATS_SLOTS` set, a run that cannot take its slot is refused: the slots' directory cannot be made, slot `i`'s file cannot be opened, its file system has no locks, or the lock is not granted after the wait. Each says `error: <what> <path>, so bats refuses to run without a machine slot (BATS_SLOTS): nothing is run` and exits 1 (`machine_slot_take`'s `SlotRefused`; `project_lock_refused` makes the dispatch skip the command, `run` included). Nothing is run and no `build/` is made. Running on without the slot would drop the machine's cap, which is what `BATS_SLOTS` is for, so the run stops instead. A `BATS_SLOTS` that is not a number from 1 to 64 is still said and ignored (above), as it was before: it names no slot that could be refused.

*Research (pwa#155, comment 6330340164, checked on util-linux 2.39.3 as root).* `flock(1)` never runs its command when it cannot open the lock file (exit 66) or when the lock is busy under `-n` (exit 1), so a run without its lock is the failure, not the default. Cargo ignores lock errors only where a file system cannot lock, and that protects a build cache per target directory, not a machine-wide cap. GNU make, when its jobserver cannot be used, runs `-j1` with a warning: a serial run is safe, a run without the lock is not. Bazel waits on its output-base lock, or fails at once under `--noblock_for_lock`. So: refuse, do not fall back.

*Proved, tested, not reproduced.* Tested for real (`tests/machine-slots`, `check` and `run` each): the directory that cannot be made (a regular file where it goes) and slot 0's file that cannot be opened (a directory where it goes); `run` is refused by its own `run_lock`, before it looks for a bin package. The no-locks refusal and the lock not granted after the wait are tested at their mapping, `slot_of_found` (where `machine_slot_take` turns what trying a slot found into a slot), by `test_unlockable_slot_is_refused`, `test_unopenable_slot_is_refused` and `test_busy_slot_after_the_wait_is_refused` in `$UNITTEST` of `src/helpers.bats`, which `bats test` runs, not CI: no file system this machine has refuses `flock(2)` (tmpfs, ext4, sysfs, procfs, /dev/shm and a FIFO all take it), and a lock that waits is not refused by the kernel for being busy. Replacing the `SlotUnlockable` or the `SlotBusy` arm of `slot_of_found` with `SlotNone()` makes its test fail.

`tests/machine-slots` compares the `BATS_SLOTS` unset and empty logs after renaming the project's name (`p5` to `p4`) on the `built` line only (bats#439). Both logs also hold the test's `mktemp` directory (bats#264's toolchain warning names `$HOME/.bats/ats2`), whose random name can contain `p5` (about 1 run in 430), so a rename over the whole log changed that path in one log and failed `cmp` at random.
